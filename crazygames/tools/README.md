# Making the covers and the preview videos

All of these drive the game in Chromium (Playwright) against the dev server: `npx vite --mode web --port 4319`. Set `PW_CHROMIUM` to use a Chromium that is already installed, as for `npm run test:browser`.

- **Stills for the covers:** `node shot3d.cjs OUTDIR WIDTH HEIGHT TAG 0 day 4 30`. This starts a race from 4th on the grid at midday, hides the HUD and saves six frames as `OUTDIR/cover/TAG-0..5.png`. The covers used `1920 1080 mid-day`, `1200 1800 port` and `1600 1600 sq`.
- **Covers:** put the chosen stills in a folder with the names `compose.cjs` expects (`mid-day-4.png`, `port-3.png`, `sq-4.png`), then run `node compose.cjs THAT_FOLDER`. It writes `cover-landscape.png`, `cover-portrait.png` and `cover-square.png`, made from the still, a paper card with the title, and Sunday Loop (`track.json`) drawn in ink. The title is in `compose.html`.
- **Preview videos:** `node record.cjs OUT.mp4 1920 1080` (and `1080 1620` for portrait: the portal wants 2:3). It runs the game on a fake clock and captures every frame, so the video is smooth at 30 fps however slow the machine is. It comes out at 20.4 s, so trim it under the portal's 20 s limit: `ffmpeg -i OUT.mp4 -t 19.5 -an -c:v libx264 -preset slow -crf 19 -pix_fmt yuv420p -movflags +faststart FINAL.mp4`. Cloud saves are blocked while it records, so the start doesn't wait on the network. The video shows Sunday Loop drawn in the editor, then raced, then raced at night in the rain. The dev-only `?autopilot` flag drives your car. Add `dry` at the end to save a few sample frames instead of a video. Needs `ffmpeg`.
